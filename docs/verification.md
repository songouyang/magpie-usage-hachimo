# 验证范围

## 发布前自动验证

使用 `tools/verify_release.py` 验证最终 Release，报告写入输出目录的 `verification.json`，不进入 Git 或公开附件。

- 指标、缺失值、真实零值、成功时间、失败／过期／恢复及锁冲突由单元测试覆盖。
- 双槽协议覆盖半写入、损坏槽、并发读、超限拒绝及文件身份保持。
- 当前已确认的 1.0.3 UI 和按键清单有内容基线；导航测试覆盖四个标签及首尾翻页。
- 官方 `validate` 检查最终组件包，`python-preview` 覆盖等待、损坏、缺失、零值、长模型名、四页、半写入和采集失败八类样例。
- 在临时目录解压最终采集器 ZIP，清空 `PYTHONPATH`，以模拟 Magpie 数据验证成功、重启后失败过期、恢复、缓存和插件读取。
- 检查组件与采集器文件白名单、源码一致性、启动器权限及 Release SHA-256 校验和。

自动测试不读取真实 Magpie 数据，不操作设备，不写 Pet Manager 正式组件库。

## 历史客户端与设备观察

2026-11-25 的现有 1.0.3 组件曾在 Pet Manager `0.1.260`、Pico 固件 `0.7.121-p4-r310-pico` 下观察到四页、标签、桌面绑定动作、撤销授权后的占位和原位文件刷新。USB 安装收到设备提交成功回执。封面来自真实客户端中的无隐私样例画面。

本次发布保持这些 UI 和按键资源，但历史观察不等于对重新打包后的每个设备行为完成新一轮实机验收。

实体键逐项按压、真机触点、LCD 观感和物理拔插恢复未经观察；没有完整的 app/snapshot 接收诊断。CLI 的 `first-data` 和安装预演用于检查结构与安装路径，曾出现 `hostSnapshot: null` 和绑定 `unobserved`，不能据此宣布设备数据链路通过。

此组件需要 PC 采集器与 Pet Manager 运行。当前 Pico 使用 USB，不支持配对 PC Wi-Fi 应用通道。其他客户端和设备由原生兼容检查判断，不承诺断开 USB 后保留最后快照。
